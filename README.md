# MD1RoBoT 🧬

**محرك تطور ذاتي متعدد اللغات يعمل محلياً بالكامل، بدون أي واجهة خارجية مدفوعة.**  
يحلل الكود، يقترح تحسينات، ويطبقها تلقائياً عبر حلقة تطور مستمرة، باستخدام نماذج ذكاء اصطناعي محلية وأدوات فحص مفتوحة المصدر.

---

## 🎯 الهدف

نظام **Agentic Evolution** قادر على تطوير أي مشروع برمجي بأي لغة (أو مزيج من اللغات).  
يعتمد على نماذج محلية عبر **Ollama**، وأدوات تحليل ثابت ومترجمات حقيقية لتقييم موضوعي.  
يعمل داخل حاوية Docker واحدة تشمل كل شيء (Rust + Ollama + أدوات اللغات).

---

## 🧠 الفلسفة

كل تعديل يمر بدورة صارمة، وليس مجرد “جرّب وشوف” عشوائي. النظام لا يكتفي بتوليد الطفرات، بل **يبني نظريات قابلة لإعادة الاستخدام**:
ملاحظة → فرضية → طفرة → تجربة → تقييم → معرفة ← نظرية



النتائج الناجحة تتراكم كمعرفة عامة (Theory Bank)، وليس كسجل تصحيحات منفصل. كل مشروع جديد يستفيد من خبرة جميع المشاريع السابقة.  
النظام ليس مجرد منفذ، بل **مختبر أبحاث هندسي ذاتي** يبني مبادئ هندسية عبر الزمن.

### أدوار الشخصيات داخل النظام

| **Crazy** | مولد الطفرات: يقرأ المشروع، يصيغ فرضية، ثم يقترح 3-5 تعديلات بأساليب مختلفة، مع قيد "Scope Guard" |

| **Theory Bank** | طبقة ذكاء معمم: يستخلص نظريات من التجارب الناجحة ويعيد استخدامها |

## 🔁 دورة التطور (Evolution Loop)

1. **بناء السياق** – تجميع حالة المشروع + النظريات ذات الصلة من `Theory Bank`.  
2. **صياغة فرضية** – يحدد Crazy ما الذي يعتقد أنه سيُحسّن الأداء (فرضية قابلة للاختبار).  
3. **توليد الطفرات** – 3-5 تعديلات بأساليب مختلفة.  
4. **التجارب المختبرية** – عزل كامل، بناء، اختبار، قياس الأداء واستهلاك الموارد.  
5. **التقييم الموزون** – مجلس (Architect/Coder/Reviewer) يعطي علامات Benefit, Novelty, Risk, Cost → درجة نهائية.  
6. **تطبيق أفضل طفرة** – بعد اجتياز Safety check (تحليل AST)، يحفظ Planner نسخة احتياطية ويدمج التعديل.  
7. **تحديث المعرفة** – تُعمم النتيجة: إذا تكررت الفرضية بنجاح، تُرفع إلى Theory مع ثقة.  
8. **العودة إلى الخطوة 1**.

## 🧠 النماذج المحلية والتوجيه (اقتصاد الطاقة)

- **النماذج الحالية**:
  - `Qwen2.5-Coder` (7B) – Python, JavaScript, TypeScript.
  - `DeepSeek-Coder` (6.7B) – Rust, C, C++, الخوارزميات.
- **التوجيه الذكي + تكلفة رقمية**: كل نموذج له وزن تكلفة (مثلاً Qwen=1, DeepSeek=6). المهام البسيطة لا تستدعي النماذج الثقيلة.
- **مجلس الحكماء (قيد التطوير)**: Architect + Coder + Reviewer معاً بدلاً من نموذج واحد، لتقليل الهلوسة وزيادة الجودة.

## 🗄️ قاعدة البيانات والمعرفة

- `genomes` – الطفرات الناجحة ولياقتها.
- `mutation_history` – سجل خام لكل تجربة.
- `knowledge` – معرفة مستخرجة من Seed.
- `theory_bank` – **نظريات معممة** (مثل "إزالة clone تحسن الأداء بنسبة 12% في مشاريع Rust") مع ثقة وعدد تجارب.
- `oscillation_log` – منع التكرار والتذبذب.
- `long_term_memory` – ذاكرة دائمة للخبرات.

## 🚫 القيود الجوهرية (غير قابلة للتجاوز)

- ❌ **ممنوع** أي تعديل يستهدف تعطيل أو حذف الوحدات الأساسية.
- ❌ **ممنوع** أي محاولة استنساخ أو نشر ذاتي على خوادم خارجية.
- ❌ **لا Abliteration** على النماذج الأساسية مطلقاً – التوجيه الهندسي الصارم هو البديل.
- ⚠️ النظام مصمم للتشغيل في بيئة معزولة. لا يُنصح بتشغيله على مشاريع إنتاجية دون مراجعة بشرية.
